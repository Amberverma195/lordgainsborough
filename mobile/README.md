# Lord Gainsborough customer app

Expo customer app for pickup ordering. It uses the existing Spring Boot API in `backend/` and does not replace the Next.js website, administrator dashboard, or kitchen display.

## Requirements

- Node.js 22.13 or newer. Expo SDK 58 and React Native 0.88 refuse older Node versions.
- The restaurant API running locally, normally on port 8082. See the repository README and `backend/TESTING.md`.
- Expo Go for SDK 58 on a phone, or an Android emulator. iOS Simulator requires macOS.

Do not point this app at production when placing test orders.

## Setup

```bash
cd mobile
npm install
copy .env.example .env
```

`EXPO_PUBLIC_API_ORIGIN` is the Spring Boot origin. `EXPO_PUBLIC_ASSET_ORIGIN` is used for menu images that are not stored under `/uploads`. `EXPO_PUBLIC_SOCKET_URL` is the Socket.IO server origin for live order tracking.

| Where the app runs | API origin | Socket.IO origin |
| --- | --- | --- |
| iOS Simulator | `http://localhost:8082` | `http://localhost:9092` |
| Android emulator | `http://localhost:8082` (rewritten to `http://10.0.2.2:8082`) | `http://localhost:9092` (rewritten to `http://10.0.2.2:9092`) |
| Physical phone (dev) | Your computer's LAN address, e.g. `http://192.168.1.20:8082` | Your computer's LAN address, e.g. `http://192.168.1.20:9092` |
| Production build | `https://api.lordgainsboroughrestaurant.ca` | `https://lordgainsborough-production.up.railway.app` (verified Railway Netty-SocketIO domain targeting port 9092) |

The Android rewrite applies only while `Constants.isDevice` is false. A physical Android device must use the LAN address.

### Required Environment Variables

All variables exposed to the mobile app must begin with the `EXPO_PUBLIC_` prefix:

- `EXPO_PUBLIC_API_ORIGIN`: Base URL for the Spring Boot REST API (port 8080). Defaults to `http://localhost:8082`. In production, set to `https://api.lordgainsboroughrestaurant.ca`.
- `EXPO_PUBLIC_ASSET_ORIGIN`: Base URL for dish images and static assets not stored under `/uploads`. Defaults to `EXPO_PUBLIC_API_ORIGIN`. In production, set to `https://api.lordgainsboroughrestaurant.ca`.
- `EXPO_PUBLIC_SOCKET_URL` (or `EXPO_PUBLIC_SOCKET_ORIGIN`): Base URL for the Netty-SocketIO server running on port 9092 that powers real-time order status updates (`order.updated`). Defaults to `http://localhost:9092`.
  > **Production requirement:** Netty-SocketIO runs on port 9092, which is distinct from Spring Boot's HTTP port 8080. In production builds (e.g. EAS Build, APK, AAB, IPA, TestFlight), set `EXPO_PUBLIC_SOCKET_URL=https://lordgainsborough-production.up.railway.app`. Omitting `EXPO_PUBLIC_SOCKET_URL` causes real-time socket connections to fall back to `http://localhost:9092` and fail on devices.

## What this version includes

Home, menu, cart, sign-in, pickup checkout, order confirmation, and account order history. Menu rows come from `GET /api/menu`, `GET /api/categories`, and `GET /api/menu/most-loved`. Checkout submits `POST /api/orders` and shows the order only after the API confirms it. Payment is at pickup.

Sign-up, password reset, profile editing, live order status polling, and real-time Socket.IO status updates are implemented. Table requests are not implemented in the mobile screens.

The logo and food photographs referenced by the website are not present in `frontend/public` in this repository. Dish photos are loaded from each menu item's `image` field. When an item has no image, the app shows a typographic monogram.

## Authentication & Credential Isolation

- **Account Session**: The mobile app stores the account JWT in Expo `SecureStore` (`lgb.session.token`). It does not use `AsyncStorage` for that token, and it does not use cookies. Signing out first revokes the current JWT on the server, then deletes the local session token. See the server-side sign-out policy below.
- **Unambiguous Account Namespaces (v2)**: Storage keys for SecureStore tracking tokens, AsyncStorage cart items, and checkout idempotency keys use a deterministic UTF-8 hex encoding (`acc_<hex>`) generated by `toAccountNamespace`. This prevents collisions between distinct email addresses (e.g. `alice+promo@example.com` and `alice_promo@example.com`) caused by lossy regex replacements (`[^a-z0-9._-]` -> `_`). Output strictly adheres to `[a-z0-9_]`, satisfying SecureStore and platform keystore character set rules.
- **Safe Legacy Demarcation (No Unsafe Migration)**: Legacy un-scoped keys and collision-prone v1 keys (`lgb.track.u.<safeEmail>...v1`, `lgb.cart.u.<safeEmail>...v1`) are never copied or migrated into v2 namespaces. They are purged during writes, signouts, and initializations to prevent cross-account credential leakage.
- **Intermediate-Render & Account-Switch Credential Protection**: `OrderDetailScreen` binds tracking credentials to the active account identity and order ID in state. On account switches or signouts, mismatched credentials evaluate to `null` synchronously on line 1 of render, preventing previous-account credentials from ever being passed to `fetchOrder`, `fetchOrderSocketTicket`, or `Socket.IO` during intermediate renders before effect cleanups run.
- **Preferred JWT-Only Authorization**: Authenticated account-owned order requests prefer JWT-only authorization (`Authorization: Bearer <jwt>`) without sending tracking tokens over the wire or to Socket.IO. Tracking tokens are reserved for unauthenticated guest order recovery.
- **Authorized Order Recovery & App Restarts**: On app restarts, active account sessions are restored and authorized tracking credentials remain accessible to the owning account for order recovery.
- **Stale-Request Cancellation**: Order detail screens cancel in-flight tracking credential lookups when switching accounts or signing out, preventing stale tokens from leaking into active queries or socket connections.

## Server-side sign-out policy

Sign out revokes the presented account JWT with POST /api/auth/logout before local session cleanup. Other devices remain signed in. New logins receive unique JWT IDs. Revocations are stored as SHA-256 digests in shared PostgreSQL until token expiry; API account authentication checks that store. Password reset and account deletion continue to invalidate account-wide identity access.

An offline/network/server failure keeps the local session and displays an unconfirmed-sign-out error so the customer can retry. A 401 means the session is already invalid and local cleanup proceeds. Existing in-flight operations may finish before revocation commits. Existing read-only order socket tickets are separate, short-lived credentials; logout does not revoke tracking links or retroactively cancel already-authorized operations. Already-open server room connections may continue until disconnected; the app disconnects its sockets when local auth is cleared. Legacy identical JWT values issued to multiple devices before unique IDs were introduced are revoked together; signing in again issues distinct sessions.

Deploy backend migration V11 and the logout endpoint before distributing this mobile version. No device-management UI or sign-out-all-devices endpoint is introduced.
